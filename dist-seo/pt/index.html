        O que ele resolve

        Os detalhes nada glamourosos que tornam um README imprimível.

        Busca

        • Dez nomes de arquivo candidatos. README.md, readme.md, README.MD e o restante, incluindo .github/.
        • Descoberta de branch. A branch padrão é lida da API, com main e master como alternativas.
        • Degradação graciosa. Uma API com limite de requisições ainda permite que a busca bruta continue.
        • Todos os formatos de URL. owner/repo, sufixos .git e links que apontam para um arquivo ou pasta.

        Resolução e renderização

        • Caminhos relativos. As imagens apontam para o conteúdo bruto, os links de documento apontam para a visualização blob e a navegação é limitada à raiz do repositório.
        • O código permanece intacto. Blocos delimitados e trechos em linha nunca são reescritos.
        • Markdown no estilo do GitHub. Tabelas, listas de tarefas, tachado e código delimitado são renderizados.
        • Saída sanitizada. Scripts, estilos, frames e formulários são removidos antes de qualquer coisa chegar à página.

        Privado por construção

        Não existe backend para onde enviar. Seu Markdown é lido, renderizado e impresso no seu próprio dispositivo — os únicos bytes que saem são os arquivos README públicos que você solicitou.
