ソフトウェアのドキュメントはリリースごとに更新されます。リポジトリのデフォルトブランチからそのまま技術文書を出力すると、未リリースの機能や破壊的変更が混入してしまう恐れがあります。[md2pdf](/#converter) を利用すれば、特定のGitブランチ、リリースタグ、またはコミットハッシュを指定して正確なバージョンのPDFを作成できます。

本記事では、Gitリファレンス指定の仕組み、適切なリファレンスの選び方、そしてバージョン整合性の高いPDFマニュアルを作成する手順を解説します。

## 技術文書においてGitリファレンス固定が不可欠な理由

エンタープライズ導入や長期サポート（LTS）向けのマニュアルを作成する場合、ドキュメントは実際に稼働しているソフトウェアバージョンと厳密に一致している必要があります。

- **本番環境との整合性**: 開発中の実験的機能ではなく、本番稼働しているAPIの仕様を正確に記載できます。
- **監査証跡とコンプライアンス**: 規制基準の監査において、不変のコミットハッシュから生成されたドキュメントは客観的な証明書として機能します。
- **過去バージョンの再現**: ローカル環境に古いリポジトリをクローンすることなく、過去の安定版マニュアルをオンデマンドで再生成できます。

```text
Supported Git Reference Types:
- Branch:  refs/heads/v2.1-maintenance
- Tag:     refs/tags/v2.1.0-lts
- Commit:  7f2b9a1d4e8c3b0f5a6d7e8c9b0a1f2e3d4c5b6a
```

## 本番マニュアルにおけるリリースタグの活用

リリースタグは、プロジェクトの安定した節目を記録したものです。md2pdfにタグ付きURLを入力するかタグセレクターから指定することで、そのリリース時点のスナップショットを正確に取得できます。

1. **タグの自動検出**: リポジトリを読み込むと、md2pdfはセマンティックバージョニング形式のタグ（例: `v1.4.0`、`v2.0.0-rc1`）を一覧表示します。
2. **スナップショットの取得**: 指定したタグ配下のファイルのみがフェッチされ、安定した内容が担保されます。
3. **バージョン情報の明記**: 表紙やヘッダーにタグ名を含めることで、閲覧者がドキュメントの対象バージョンを一目で把握できます。

## メンテナンスブランチの指定

旧バージョンのバグ修正が進行している場合、更新されたドキュメントは専用の保守ブランチにコミットされます。

`support/3.x` や `v1-stable` といったブランチ名を指定することで、md2pdfはその保守ラインの最新ドキュメントを取得します。メインブランチの不安定なコードを避けて適切な指示書を出力できます。

## コミットSHAによる完全な不変エクスポート

ドキュメントの再現性を極限まで高めるには、40文字のコミットハッシュ（SHA）の指定が有効です。ブランチや可変タグとは異なり、コミットハッシュは数学的に不変です。

md2pdfでコミットSHAを指定すると、リポジトリ履歴上の該当時点のGitツリーが再現されます。将来ブランチが削除されたり履歴が改変されたりした場合でも、生成されたPDFは検証済みの状態を確実に保持します。

## md2pdfにおけるリファレンス切り替え手順

md2pdfでのリファレンス設定はシンプルです:

1. リポジトリURLを入力欄に貼り付けます。
2. リファレンス選択ドロップダウンを開き、利用可能なブランチやタグを確認します。
3. 目的のタグやブランチを選択するか、特定のコミットハッシュを直接入力します。
4. ファイルツリーを確認し、バージョンが固定された美しいPDFドキュメントを生成します。
