複数のフォルダに分散したドキュメント群を1冊のPDF電子書籍として統合する場合、数十個のファイルを1つずつ手動で選択するのは非効率です。章ごとの細かい選択精度を保ちながら、フォルダ全体を一括でオン・オフできる操作性が求められます。[md2pdf](/#converter) に搭載された「3状態（トリステート）フォルダ選択チェックボックス」により、技術マニュアルの編成を直感的かつ確実に行えます。

本ガイドでは、ディレクトリ単位チェックボックスの動作原理、3状態インジケーターの役割、複数フォルダにまたがるMarkdownドキュメントを美しいPDF書籍にまとめる手順を解説します。

## ディレクトリチェックボックスの「3つの状態」の理解

階層化されたファイル管理において、単純な「オン/オフ」の2値モデルでは一部のファイルのみが選択された中間状態を表現できません。md2pdfは標準的な3状態チェックボックスモデルを採用しています:

1. **選択（全選択状態）**: フォルダ内およびそのすべてのサブディレクトリにあるMarkdownファイルがすべてエクスポート対象になっています。
2. **中間状態（一部選択状態）**: フォルダ内のファイルの一部のみが選択され、一部は除外されている状態です。
3. **未選択（全解除状態）**: 当該ディレクトリおよびその配下のファイルは一切エクスポート対象に含まれていません。

```text
Tri-State Folder Hierarchy:
[-] docs/guides/             (Indeterminate: partially selected)
    [x] getting-started.md   (Selected)
    [ ] advanced-config.md   (Excluded)
[x] docs/api/                (Checked: all files selected)
    [x] endpoints.md         (Selected)
    [x] authentication.md    (Selected)
```

## カスケード選択ロジックの動作

フォルダのチェックボックスをクリックすると、ツリー全体に連動するカスケード処理が実行されます:

- **下方向への伝播**: 未選択フォルダをクリックすると、その配下のすべてのファイルとサブフォルダが一括選択されます。選択済みまたは中間状態のフォルダをクリックすると、配下のすべての選択が解除されます。
- **上方向へのバブリング**: 子ファイルを個別に選択・解除すると、ルートに至る親フォルダの状態が自動的に再計算されます。配下の全ファイルが選択されると、親フォルダは自動的に「全選択」に切り替わります。
- **直感的な視覚フィードバック**: 中間状態のダッシュ記号（-）により、フォルダを展開しなくても内部で一部選択が行われていることが即座にわかります。

## 用途に応じた技術ハンドブックの編集

3状態フォルダコントロールにより、目的に合わせた技術ドキュメントの編纂が数秒で完了します:

- **モジュール別開発者ガイド**: `api/` と `sdk/` フォルダのみを選択し、社内用の `admin/` や `ops/` を除外して外部向け仕様書を作成。
- **監査用コンプライアンス集**: 監査フォルダ全体を選択した上でドラフト段階のファイルのみを除外し、公式提出用PDFを生成。
- **オンボーディング資料**: ルートの `README.md` と `tutorials/getting-started/` フォルダ内の入門ガイドのみを合本。

## PDFコンパイル時の階層構造の維持

選択したフォルダ群を単一のPDFブックにコンパイルする際、md2pdfはドキュメントの論理的な階層構造を保持します:

- **階層化された目次**: フォルダが大きな部（セクション）となり、各Markdownファイルが章として目次に自動構成されます。
- **通しページ番号**: 結合されたすべてのドキュメントにまたがり、途切れのない連続ページ番号が付与されます。
- **明確な改ページ**: ファイルとファイルの間には自動的に改ページが挿入され、清潔感のある製本品質を保ちます。

## カスタム書籍のPDFエクスポート

フォルダ選択が完了したら、コンパイルボタンをクリックしてドキュメントを生成します。厳選されたMarkdown文書が、高品位なタイポグラフィと目次リンクを備えたプロ仕様のPDF書籍として出力されます。
