複数のMarkdownファイルを1冊のPDF技術書にまとめる際、ファイル名のアルファベット順が常に最適な読書の流れになるとは限りません。入門編は詳細な仕様書の前に置くべきであり、初期設定手順はトラブルシューティングより先に来る必要があります。[md2pdf](/#converter) の章順並び替え機能を使用すれば、選択したドキュメントを自由自在に再配置できます。

本記事では、md2pdfにおける章順変更の仕組み、階層管理のポイント、出版品質のPDF書籍を編纂する実践的なノウハウを解説します。

## 技術文書の合本において順序付けが重要な理由

リポジトリ内のファイル名は、読者の読みやすさではなく開発者の命名規則に従ってつけられていることが一般的です。

- **非線形なファイル名**: `getting-started.md` や `architecture.md` は、アルファベット順では論理的な流れと食い違います。
- **読みやすさの確保**: 技術解説には「はじめに、前提条件、導入手順、基礎概念、リファレンス」という段階的な導入が不可欠です。
- **目次構成の整合性**: 生成されるPDFの目次ツリーは、画面上で設定した章の順序と完全に一致します。

```text
Optimized Chapter Order Example:
01. README.md              -> Title & Introduction
02. docs/install.md        -> Prerequisites & Setup
03. docs/quickstart.md     -> First Hands-on Tutorial
04. docs/architecture.md   -> Internal Architecture
05. docs/api-reference.md  -> Complete API Specifications
```

## md2pdfのインタラクティブな並び替え操作

md2pdfでは、コンパイル前にドキュメントの順序を直感的に調整できるコントロールを提供しています:

1. **上へ・下へ移動**: ワンクリックで選択した章をキューの中で前後に移動できます。
2. **処理キューの可視化**: ドキュメントが結合される正確な順序を一覧画面でいつでも確認できます。
3. **リセットと自動整列**: 必要に応じて、リポジトリ本来の順序やアルファベット順にワンクリックで戻すことができます。

## 各章にまたがる見出し階層の統一

複数ファイルを結合する際、md2pdfは見出しレベルを自動的に正規化し、統一感のある文書構造を維持します:

- **章タイトルの割り当て**: 各ファイルのトップレベル見出しが、目次における独立した章タイトルとして扱われます。
- **サブセクションの維持**: ファイル内のH2やH3見出しは章配下の節として整理され、PDFリーダーのしおり構造に反映されます。
- **適切な改ページ**: 章と章の間には自動的に改ページが挿入され、見栄えの良いレイアウトが保証されます。

## 章間リンクの自動解決と内部ジャンプ機能

複数ファイルのリポジトリでは、`[設定ガイド](config.md)` のように相対パスで相互リンクが張られていることがよくあります。

md2pdfはコンパイル時にこれらの相対リンクを解析し、PDF内の内部ジャンプリンクに変換します。読者は第1章から第4章の該当箇所へとスムーズに移動できます。

## 順序付けされたPDF書籍のコンパイル

理想的な読書順序への配置が完了したら、コンパイルボタンをクリックします。md2pdfはすべての章をブラウザメモリ内で統合し、均一なタイポグラフィと連続ページ番号を付与して完成度の高いPDF書籍を書き出します。
