大規模なモノレポや広範なドキュメントサイトでは、深くネストしたディレクトリ内に数百ものMarkdownファイルが分散して配置されています。目的のガイドを探すためにフォルダを1つずつ開いていく作業は非効率的です。[md2pdf](/#converter) に搭載されたリアルタイム検索とパスフィルターを使えば、必要な文書を数ミリ秒で絞り込むことができます。

本記事では、md2pdfによるクライアントサイド検索の動作仕様、パス対応マッチング、目的の文書のみを効率的にPDF出力する手順について解説します。

## 大規模ドキュメントナビゲーションの課題

最新のソフトウェア開発では、APIリファレンス、チュートリアル、運用マニュアル、アーキテクチャ設計書が単一のリポジトリに同居することが一般的です。

- **膨大なファイル数**: 大規模フレームワークでは、数百を超えるMarkdownファイルが存在することも珍しくありません。
- **深い階層構造**: ファイルが4階層から5階層以上の深さに格納されているケースがあります。
- **ファイル名の重複**: 各ディレクトリに `index.md` や `overview.md` が存在し、相対パスなしでは目的のファイルを特定しにくい問題が生じます。

```text
Search Query Example: "auth/jwt"
Matches:
- docs/services/auth/jwt-validation.md
- guides/security/auth/jwt-tokens.md
Excluded:
- docs/services/billing/invoices.md
```

## ブラウザ内リアルタイム検索の仕組み

md2pdfの検索フィルターは、ファイルツリーの読み込み時に構築されるインメモリアドレスインデックスを用いて、すべてブラウザ内でローカルに実行されます。

検索ボックスに文字を入力すると:

1. **瞬時の評価**: 追加のネットワーク通信やページ遷移を行うことなく、入力と同時に即座に結果を反映します。
2. **部分一致とパス評価**: ファイル名だけでなく親ディレクトリのパスも対象となるため、`api/v2` と入力すれば該当フォルダ内のドキュメントが一挙にヒットします。
3. **ツリーの自動展開**: 一致したノードは自動的に展開され、一致しないフォルダは非表示となるため、対象ファイルを一目で把握できます。

## 絞り込んだファイルの一括選択

検索で抽出したファイルは、簡単な操作で変換対象に指定できます:

- **一括選択**: フィルター適用中にマスターチェックボックスを操作することで、現在画面に表示されている該当ファイルのみを一括選択できます。
- **個別調整**: 検索結果の中から不要なメモなどを個別に除外することも可能です。
- **クリア時の選択維持**: 検索キーワードを消去してツリー全体を再表示しても、フィルター中に選択したチェック状態はそのまま保持されます。

## 大量ドキュメントに対するパフォーマンス維持

md2pdfは軽量な文字列インデックスと効率的なDOM描画を採用しているため、数千ファイル規模のリポジトリでもストレスのない軽快なレスポンスを実現します。

検索段階ではパス文字列のみを処理するためメモリ消費もごくわずかであり、PDFレンダリング処理に必要なマシンパワーを無駄に消費しません。

## 抽出したドキュメントセットのPDF出力

検索とファイル選択が完了したら、コンパイルボタンを押してPDFを作成します。抽出した章を1冊にまとめた統合PDF電子書籍として書き出すか、個別PDFのZIPアーカイブとして出力するかを自由に選択できます。
