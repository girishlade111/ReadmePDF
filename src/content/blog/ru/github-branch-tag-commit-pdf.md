Документация к программному обеспечению обновляется с каждым новым релизом. Если экспортировать руководство из ветки по умолчанию, велик риск включить еще не выпущенные функции или экспериментальные изменения API. С помощью [md2pdf](/#converter) вы можете зафиксировать экспорт на конкретных ветках Git, релизных тегах или неизменяемых коммитах.

В этом руководстве объясняются механизмы фиксации ссылок Git, выбор подходящего типа указателя и подготовка точных версионных документов PDF.

## Зачем нужна фиксация Git-ссылок в технической документации

При подготовке инструкций для корпоративных установок или версий с длительным сроком поддержки (LTS) текст должен в точности соответствовать развернутому программному обеспечению.

- **Точность для рабочей среды**: Гарантия того, что руководство описывает работающие в данный момент функции, а не будущие правки.
- **Аудит и сертификация**: При прохождении независимых проверок документация, сгенерированная из неизменяемого хэша коммита, служит подтверждением состояния системы.
- **Сохранение архивов**: Возможность мгновенно воссоздать документацию к старым версиям без клонирования объемных репозиториев на локальный диск.

```text
Supported Git Reference Types:
- Branch:  refs/heads/v2.1-maintenance
- Tag:     refs/tags/v2.1.0-lts
- Commit:  7f2b9a1d4e8c3b0f5a6d7e8c9b0a1f2e3d4c5b6a
```

## Использование релизных тегов для стабильных руководств

Теги релизов фиксируют проверенные контрольные точки в жизненном цикле разработки. При указании ссылки с тегом в md2pdf клиент загружает файлы строго из этого состояния.

1. **Обнаружение тегов**: При обработке репозитория md2pdf находит теги семантического версионирования (например, `v1.4.0`, `v2.0.0-rc1`).
2. **Получение снимка**: Каждый скачиваемый файл соответствует состоянию проекта на момент публикации релиза.
3. **Обозначение версии**: Добавьте имя тега на титульный лист или в верхний колонтитул, чтобы пользователи сразу видели версию документа.

## Экспорт из веток поддержки (Maintenance Branches)

Когда инженеры выпускают исправления безопасности для прошлых релизов, изменения часто вносятся в специализированные ветки сопровождения.

Указывая такую ветку, как `support/3.x` или `v1-stable`, md2pdf загружает свежие обновления документации именно из нее, предотвращая попадание нестабильного кода из основной ветки.

## Полная неизменяемость с помощью SHA коммита

Для стопроцентной воспроизводимости ничто не сравнится с точным 40-значным хэшем коммита Git. В отличие от веток или переназначаемых тегов, коммит математически постоянен.

При указании хэша в md2pdf дерево Git считывается строго в этот исторический момент. Даже если ветка будет удалена впоследствии, ваш сгенерированный PDF останется достоверным снимком проверенного состояния.

## Пошаговая настройка ссылок Git в md2pdf

Указать целевую ссылку в md2pdf можно за несколько секунд:

1. Вставьте адрес репозитория в поле ввода.
2. Откройте выпадающее меню ссылок, чтобы просмотреть доступные ветки и теги.
3. Выберите нужный тег или ветку либо введите хэш коммита напрямую.
4. Проверьте дерево файлов и скомпилируйте зафиксированные документы в аккуратный PDF.
