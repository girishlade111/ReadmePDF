소프트웨어 문서는 릴리스가 진행됨에 따라 끊임없이 변화합니다. 저장소의 기본 브랜치에서 문서를 그대로 내보내면 아직 정식 출시되지 않은 실험적 기능이나 변경된 API 사양이 포함될 수 있습니다. [md2pdf](/#converter)를 활용하면 특정 Git 브랜치, 릴리스 태그, 커밋 해시를 지정하여 원하는 시점의 마크다운을 정확하게 PDF로 제작할 수 있습니다.

이 가이드에서는 Git 참조 고정의 필요성, 상황별 참조 선택 방법, 신뢰할 수 있는 버전별 PDF 매뉴얼 제작 절차를 다룹니다.

## 기술 문서에서 Git 참조 고정이 중요한 이유

엔터프라이즈 환경이나 장기 지원(LTS) 버전용 매뉴얼을 배포할 때는 현재 설치된 소프트웨어 버전과 문서 내용이 일치해야 합니다.

- **운영 정확성**: 개발 중인 미출시 기능 대신 현재 상용 환경에 배포된 API 사양만을 정확히 전달합니다.
- **감사 및 규정 준수**: 공인 인증이나 보안 감사 진행 시, 불변의 커밋 해시에서 생성된 문서는 명확한 검증 자료가 됩니다.
- **과거 릴리스 보존**: 로컬 컴퓨터에 과거 버전의 저장소를 복제할 필요 없이 이전 릴리스 문서를 손쉽게 다시 제작할 수 있습니다.

```text
Supported Git Reference Types:
- Branch:  refs/heads/v2.1-maintenance
- Tag:     refs/tags/v2.1.0-lts
- Commit:  7f2b9a1d4e8c3b0f5a6d7e8c9b0a1f2e3d4c5b6a
```

## 안정적인 운영 매뉴얼을 위한 릴리스 태그 활용

릴리스 태그는 프로젝트의 안정된 이정표를 나타냅니다. md2pdf에 태그가 포함된 URL을 입력하거나 인터페이스에서 태그를 선택하면 해당 시점의 파일 스냅샷을 즉시 불러옵니다.

1. **태그 자동 탐색**: 저장소를 조회하면 md2pdf가 `v1.4.0`, `v2.0.0-rc1`과 같은 유의적 버전 태그 목록을 감지합니다.
2. **스냅샷 호출**: 선택된 태그의 기준 시점에 고정된 문서 파일들만 정확하게 다운로드됩니다.
3. **버전 표기**: 표지나 헤더에 태그 버전을 기재하여 독자가 문서의 적용 범위를 명확히 인지할 수 있도록 돕습니다.

## 유지보수 브랜치 문서 불러오기

이전 메이저 버전에 대한 보안 패치나 버그 수정이 이루어질 때 기술 문서는 별도의 유지보수 브랜치에 업데이트됩니다.

`support/3.x` 또는 `v1-stable`과 같은 브랜치를 지정하면 md2pdf는 해당 유지보수 라인의 최신 문서를 가져옵니다. 이를 통해 메인 브랜치의 불안정한 변경 사항을 배제하고 검증된 지침서만을 추출할 수 있습니다.

## 커밋 SHA를 통한 영구 불변 문서 생성

문서의 완전한 재현성을 확보하기 위해서는 40자리 Git 커밋 해시(SHA)를 사용하는 것이 가장 안전합니다. 커밋 해시는 변경이 불가능한 고유 식별자입니다.

md2pdf에서 커밋 SHA를 지정하면 저장소 기록의 특정 순간으로 Git 트리가 복원됩니다. 향후 브랜치가 삭제되거나 히스토리가 재작성되더라도 추출된 PDF 문서는 당시 검증된 상태를 영구히 보존합니다.

## md2pdf에서 Git 참조 설정하는 단계

md2pdf에서 원하는 참조를 설정하는 과정은 매우 간단합니다:

1. 저장소 주소를 입력창에 붙여넣습니다.
2. 참조 선택 메뉴를 열어 이용 가능한 브랜치와 태그 목록을 확인합니다.
3. 대상 태그나 브랜치를 선택하거나 커밋 해시를 직접 입력합니다.
4. 파일 트리를 확인한 후 완벽하게 버전이 고정된 고품질 PDF 문서를 컴파일합니다.
